# The creator — what a motion-graphics build needs to know

The creator runs an AI/automation YouTube channel and an outbound/GTM agency. They teach tools
like **Clay, n8n, Instantly, HeyReach, Prospeo, Apify, Grok, Cursor, Claude Code and Codex**,
usually by building live on screen.

## Who watches

AI/automation practitioners with an outbound core: GTM engineers, agency operators, Clay/n8n
builders and technically curious founders. They already know Clay, Instantly, MCP and Cursor, so a
real product mark on screen is instant recognition. That is why every named tool gets its official
logo (`library/design.md` §9).

## How they talk

An operator thinking out loud. Direct, with casual asides ("potato potato", "it just rips", "I
digress"), and constant analogies to hiring and onboarding employees. They frame things as "best
practices, not rules".

The analogies are the best source of visuals. Draw the analogy, not the jargon:

- **Context + capability.** An agent is a new employee: give it the handbook (context) and the
  tools (capability). Good visual: a core that receives a document and a row of tool plates.
- **Stay model-agnostic.** Don't get cornered into one model; hop between Cursor, Claude Code,
  Codex, Antigravity. Good visual: one core, swappable model plates.
- **CLI tools over MCP where possible.** Lighter on context. Good visual: a slim pipe versus a
  heavy one filling the context meter.

## Honesty

The creator teaches setup far more often than they show results. A graphic never implies revenue,
replies, booked meetings or any number that wasn't said and shown. No fabricated screenshots,
dashboards, tweets or UI you have not actually seen.
